## 2. Badge cleanup — expo 9

`visitors` on expo 9 with `badge_id ~ '^BADGE-[0-9]{13}'`:

```
before = 2,869
after  = 0
```

Backup: `visitors_badge_backup_20260909` (2,869 rows: id, expo_id,
old_badge_id, qr_code). **Keep until post-fair (post-24 Sep)** in case
of rollback. Post-fair DROP is on todo.md.

Update statement:
```sql
UPDATE visitors
SET badge_id = UPPER(SUBSTRING(qr_code FROM 1 FOR 8))
WHERE expo_id = 9
  AND badge_id ~ '^BADGE-[0-9]{13}'
  AND qr_code IS NOT NULL AND qr_code != '';
```

Matches the hex-8 shape used by every other registration path.
Prospective normalisation deployed earlier the same day in commit
`6ccfdb3` — new zoho rows land as hex-8 automatically now.

The cleanup did NOT extend to the other 18 expos (see §4). First

## 7. NULL-date sort bug found post-4b69814

Post-deploy Suer observed the id=16 "test" expo (both dates NULL)
rendering "Jan 1, 1970" and sorting FIRST. Root cause: the boolean
first-sort-key `(end_date < CURRENT_DATE) ASC NULLS FIRST` sinks the
NULL comparison result to the top. Fix: three-way CASE bucket ({0
active/upcoming, 1 ended, 2 NULL-dated}). Verified against live data
before ship. Fix in same-day commit `5ca4b9d`.
